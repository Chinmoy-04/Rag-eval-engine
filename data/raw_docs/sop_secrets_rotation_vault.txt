1. PURPOSE & SCOPE
This SOP defines the technical requirements for generating, storing, injecting, 
and rotating cryptographic secrets, API keys, database credentials, and TLS 
certificates across all HelixForge production and staging environments.

2. CORE SECRETS STANDARDS
- All production secrets must reside exclusively in HashiCorp Vault Enterprise (see software_catalog.csv).
- Hardcoding secrets in git repositories, Dockerfiles, or Slack channels is a SEV-1 security violation.
- Secret Time-To-Live (TTL): Standard API credentials and database passwords must rotate automatically every 90 days.
- Dynamic Short-Lived Secrets: Database bastions and production SSH use ephemeral certificates with an 8-hour maximum TTL (see sop_production_ssh_yubikey.txt).

3. SCHEDULED 90-DAY ROTATION WORKFLOW
Step 3.1: Automated Alert: Vault triggers a rotation notice to the owning team 14 days before TTL expiry.
Step 3.2: Dual-Key Overlap: Vault generates new secret version while keeping previous secret valid for a 48-hour overlap window.
Step 3.3: Hot-Reload Deployment: Kubernetes pods re-read secrets via Vault Agent sidecars without downtime.
Step 3.4: Revocation: Vault revokes the older secret at T+48 hours and logs confirmation to SecOps SIEM.

4. EMERGENCY BREACH ROTATION (SEV-0 / SEV-1)
In the event of an unauthorized secret disclosure:
Step 4.1: CISO or Incident Commander triggers emergency rotation CLI:
          $ hf-vault emergency-rotate --path secret/data/prod/cluster-auth --immediate
Step 4.2: Revocation of all active session tokens issued before breach timestamp.
Step 4.3: Post-incident investigation logged in SEC-VULN within 24 hours.

5. AUDIT LOGGING & COMPLIANCE
- Vault audit devices stream HMAC-SHA256 hashed audit logs to AWS CloudWatch and immutable S3 Glacier storage.
- Log retention requirement is 365 days per records_retention.md and SOC 2 Type II controls.
